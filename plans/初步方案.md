## 〇、写在前面：这是一场比赛，先赢"纸面"

在动手焊一块板子之前，必须先把这场比赛的**数学结构**算清楚。Robocon 的胜负极少取决于"谁的机器人更酷"，而取决于**谁的策略在单位时间内得分效率更高、且能稳定复现**。下面先做深度分析，再谈怎么做。

---

## 一、深度分析：拆解比赛的得分结构

### 1.1 把 180 秒变成一道优化题

| 得分项 | 单次分值 | 说明 |
|--------|:------:|------|
| TR 交接 1 块 | 5 | 永久有效，量大，是"现金流" |
| L1 完整塔 | 70 | 10+20+40 |
| **L2 完整塔** | **140** | 20+40+80，**是 L1 的 2 倍** |
| **秘宝** | **250** | 单项最高，但有前置门槛 |

**三个决定性洞察：**

1. **秘宝 250 分是胜负手，但它是一道"门槛题"。**
   要拿秘宝必须先满足**圣所条件：≥2 座完整塔，且其中 ≥1 座在共享区**。
   → 意味着"快速起 2 座塔（含 1 座共享区）→ 解锁秘宝 → 250 分落袋 → 再回头刷塔"是主流剧本。
   → 一旦取走秘宝即**永久解锁**（规则 3.6.2），所以**越早解锁越安全**，不必保塔到最后。

2. **L2 的单塔价值是 L1 的两倍，但代价是"更高 + 共享"。**
   - L2 高 900 mm、整块是共享区（对方也能来建/来抢）、建塔位少。
   - 但平分判定第 2 条就是"**L2 上正确放置的方块总数**多者胜"——L2 不仅是高分区，还是**平局时的关键筹码**。
   → 结论：**L1 求稳保底，L2 才是拉开差距的战场**。能力够就必须上 L2。

3. **天空块的"颜色即归属 + 可翻转夺取"是隐藏的对抗点。**
   - 塔的地基块归属看"谁放的"，但**天空块归属看结束时朝上颜色**。
   - 你可以把对方塔顶的天空块翻成自己的颜色 → **白捡一座完整塔的顶层分（L1 40 / L2 80）+ 改变完整塔归属**。
   → 这是一个低成本高回报的"偷分"动作，但要占用 BR 宝贵的作业时间。属于**中后期战术选项**，前期不必优先。

### 1.2 系统瓶颈：整条流水线是"串联"的

```
储存区/共享区 --TR采集--> 交接区 --BR取块--> 建塔位 --BR堆叠--> 完整塔 --> 秘宝
   (地面)                 (L1)              (L1/L2)            (解锁)   (中央柱)
```

**总吞吐 = min( TR 采集运输节拍 , BR 取块建塔节拍 )**，任何一环慢，全链慢。

- TR 一次最多 3 块，一座塔要 3 块（2 地基 + 1 天空）→ **TR 跑 1 趟 ≈ 供 1 座塔**。
- BR 一次最多 2 块 → 一座塔 BR 至少跑 2 趟（或在塔位旁周转）。
- **TR 与 BR 严禁无线通信**（规则 11.10）→ 交接全靠交接区这个"物理缓冲"，时序无法实时协商，**交接流程必须高度鲁棒、容错**。

**推论：** TR 的"采集—运输—卸货"循环速度是整队的**心脏起搏器**。TR 哪怕只做手动，也要把这条循环练到肌肉记忆级别。

### 1.3 风险清单（按致命程度排序）

| 风险 | 影响 | 对策方向 |
|------|------|---------|
| BR 爬不上 600/900 mm 平台 | 全盘皆输 | **优先走 3.5 m 长斜坡**（坡度仅 ~10°），规避爬台阶机构 |
| BR 全自动堆叠精度不够 | 塔倒塌、不得分 | 视觉伺服 + 机械限位 + 闭环放置 |
| 秘宝球滚落 | 250 分丢失 | 凹槽自对中设计 + 放置后确认稳定再松手 |
| 交接失败/掉块 | 违规、浪费时间 | 交接区做"放置台"，TR 放、BR 取，避免空中对接 |
| 全自动决策混乱 | 卡死、重试丢时间 | 行为树状态机 + 完善的异常恢复 |
| 无线信号差（规则明确不保证） | 手动 TR 失控 | TR 也尽量自主化；手动做冗余 |

## 二、总体技术路线（双机器人）

```
┌──────────────────────────┐         ┌──────────────────────────┐
│   TR 运输机器人 (地面)     │  物理   │   BR 建造机器人 (L1/L2)    │
│  ─ 快速全向底盘            │  交接   │  ─ 全自主 (ROS2)           │
│  ─ 多工位方块存储 (≤3)     │  区     │  ─ 爬楼底盘 (走斜坡)        │
│  ─ 采集/卸货机构           │ ═════> │  ─ 举升+夹爪堆叠机构        │
│  ─ 手动为主 + 自主辅助      │ (禁通信)│  ─ 视觉识别+精准放置         │
│  ─ 可取秘宝交接给 BR       │         │  ─ 翻块/放秘宝             │
└──────────────────────────┘         └──────────────────────────┘
        两台独立 ROS2 系统，物理隔离，禁止无线互联
```

**核心战略（默认打法）：**
> **Phase A 抢门槛**：TR 高速供块，BR 最快在 L1 起 1 座专属区塔 + 1 座共享区塔 → 解锁圣所 → TR 取秘宝交 BR → BR 上 L2 放秘宝（250 分到手）。
> **Phase B 拉差距**：秘宝落袋后，BR 主攻 L2 高倍率塔，TR 持续供块刷交接分。
> **Phase C 收尾偷分**：时间将尽时，视情况翻转对方塔顶天空块 / 巩固己方 L2 方块数（平局筹码）。

## 三、TR 运输机器人方案

**定位：得分现金流 + BR 的"供料线"。方案已定：纯手动，主攻 BR。**

| 模块 | 方案 | 理由 |
|------|------|------|
| 底盘 | 四驱麦克纳姆轮 / 全向轮 | 地面区+共享区需频繁平移、原地对准，全向最灵活 |
| 采集 | 前叉式/抱夹式取块，兼容 350 地基块 & 200 天空块 | 一种机构吃两种块，减少复杂度 |
| 存储 | 立式 3 工位缓存架（≤3 块） | 一次取 3 块跑一趟供 1 座塔 |
| 卸货 | 举升 + 倾倒/推送至交接区放置台 | 放下即走，不与 BR 空中对接 |
| 控制 | **纯手动（手柄遥控）**（已定） | 规则允许 TR 手动；把全部研发精力投向 BR 全自动；遥控链路用 Wi-Fi/蓝牙（规则 11.8） |
| 感知 | 从简（仅底盘里程计/限位），不上自主导航 | 手动驾驶无需环境感知，降低复杂度 |

**TR 的关键指标：单次"采集→运输→卸货"循环时间。目标压到 ~20 s 内，全靠操作手熟练度 + 机构快循环。**

## 四、BR 建造机器人方案（难点核心）

**定位：全队技术天花板，必须全自动。**

### 4.1 移动与爬楼（最高优先级）—— ⚠️ 注意规则约束
- **地面→L1 走斜坡（已定）**：高 600 mm，斜坡长 3500 mm，**坡度 ≈ 9.7°**，普通轮式底盘可稳定爬升，规避最陡路段的爬台阶风险。
- **⚠️ 关键约束：L1→L2 规则只允许走阶梯**（高差 300 mm，**2 级 × 150 mm**，每级 300×1000×150 mm），**没有斜坡**。而放秘宝必须让 BR 本体登上 L2 → **BR 底盘必须具备爬 2 级 150 mm 台阶的能力**。
- **底盘选型结论**：大轮径全向轮（≥200–250 mm，台阶高 < 轮半径）+ 独立悬挂/前越障辅助，兼顾"全向精细对准"与"150 mm 台阶越障"。详见 [详细设计.md](详细设计.md)。
- 精确定位：场地固定 → **预制地图 + AMCL**；平台边缘/建塔位用视觉 + 超声/TOF 补盲，防止跌落。

### 4.2 堆叠机构
- **举升 + 夹爪**：竖直升降台（剪叉/丝杠）把块举到目标高度，夹爪放置。
- 需把 350 mm 块叠到 700 mm、再于 ~900 mm 高处放 200 mm 天空块；中央柱放秘宝高度 800 mm。
- **展开高度上限 1200 mm**——举升行程须在折叠（≤700）与展开（≤1200）间精巧设计。
- 放置精度靠"**机械限位 + 视觉伺服闭环**"双保险：先粗定位，再相机精调，最后缓放。

### 4.3 感知（全自动的眼睛）
- **RealSense 深度相机**：识别地基块/天空块位置姿态、识别天空块**颜色朝向**、识别建塔位（绿色 500×500）、对准中央柱凹槽。
- 颜色识别用 HSV 阈值 + 形状（轮廓/连通域）即可，方块是规则立方体，**不必上重型深度学习**，保证实时性与可解释性。
- 柱顶凹槽对中：利用凹槽直径 180 mm 的约束做自对中。

### 4.4 决策（大脑）
- **行为树（Behavior Tree）状态机**：
  `取块 → 移动到建塔位 → 视觉对准 → 堆叠 → (满足圣所?) 取秘宝 → 上 L2 → 放秘宝 → 刷塔/翻块`
- 每个节点带**失败检测与恢复分支**（抓取失败重试、对准失败重定位、块掉落上报）。

## 五、ROS 2 软件架构（Humble）

```
┌──────────────────────── 感知层 ────────────────────────┐
│ realsense2_camera · cv_bridge · OpenCV(HSV/轮廓)        │
│ 激光雷达驱动 · AprilTag/色块定位                         │
├──────────────────────── 定位层 ────────────────────────┤
│ 预制地图 map_server · AMCL · robot_localization(轮+IMU) │
├──────────────────────── 规划层 ────────────────────────┤
│ Nav2 (costmap 处理坡道) · 视觉伺服局部微调               │
├──────────────────────── 控制层 ────────────────────────┤
│ ros2_control (底盘+举升+夹爪) · 可选 MoveIt2 (若用机械臂) │
├──────────────────────── 决策层 ────────────────────────┤
│ BehaviorTree.CPP 任务状态机 · 异常恢复 · 计分策略        │
└─────────────────────────────────────────────────────────┘
```

**建议的工作空间包结构（`src/`）：**

| 包名 | 职责 |
|------|------|
| `rc_bringup` | 启动文件、参数、整机 launch |
| `rc_description` | 机器人 URDF/SDF、仿真模型 |
| `rc_perception` | 方块/颜色/建塔位识别 |
| `rc_localization` | 地图、AMCL、传感器融合 |
| `rc_navigation` | Nav2 配置、爬楼控制 |
| `rc_manipulation` | 举升/夹爪/堆叠动作 |
| `rc_behavior` | 行为树决策、任务编排 |
| `rc_teleop` | TR 手动遥控（手柄） |
| `rc_msgs` | 自定义消息/动作接口 |
| `rc_sim` | Gazebo 仿真、场地模型 |

## 六、分阶段实施路线图

> 原则：**先能跑、再能得分、再得高分、最后全自动。** 每个阶段都要"可上场比赛"。

| 阶段 | 目标 | 里程碑 |
|------|------|--------|
| **P0 准备** | 吃透规则、1:1 搭场地、定接口 | 场地/道具就位，尺寸误差 ≤5% |
| **P1 TR 先行** | 手动 TR 跑通"采集—运输—交接" | 循环 ≤25 s，稳定不违规 |
| **P2 BR 底盘** | 全向底盘 + **爬斜坡**上 L1/L2 | 满载稳定上下 600/900 mm |
| **P3 BR 建塔** | 视觉对准 + 举升堆叠 | L1 稳定起 1 座完整塔 |
| **P4 解锁秘宝** | 跑通"2 塔→取秘宝→上 L2→安放" | 全场流程连贯，秘宝 250 分 |
| **P5 全自动** | BR 行为树全自主 + TR 自主化 | 无人干预跑完整场 |
| **P6 对抗强化** | L2 高分塔 + 翻块偷分 + 抗干扰 | 双机对抗演练、压平局筹码 |

## 七、怎么操作：从零起步的具体步骤

> 以下命令均在 Ubuntu 22.04 + ROS 2 Humble 环境下执行。你的环境已装好 Humble、`nav2`、`cv_bridge`，可直接从第 3 步开始。

### 步骤 1：确认 / 安装 ROS 2 Humble
```bash
# 检查是否已安装（应输出 humble）
ls /opt/ros/
# 若未安装，参考官方文档安装 ros-humble-desktop，并：
sudo apt update
sudo apt install -y python3-colcon-common-extensions python3-rosdep
```

### 步骤 2：安装本项目所需依赖
```bash
sudo apt install -y \
  ros-humble-navigation2 ros-humble-nav2-bringup \
  ros-humble-cv-bridge ros-humble-vision-opencv \
  ros-humble-robot-localization \
  ros-humble-ros2-control ros-humble-ros2-controllers \
  ros-humble-realsense2-camera \
  ros-humble-joy ros-humble-teleop-twist-joy \
  python3-opencv python3-pip
pip3 install py_trees   # 或改用 BehaviorTree.CPP
```

### 步骤 3：创建工作空间并初始化包
```bash
cd ~/ROS2/27RC
mkdir -p src && cd src

# 生成各个功能包骨架
for pkg in rc_bringup rc_perception rc_localization rc_navigation \
           rc_manipulation rc_behavior rc_teleop rc_sim; do
  ros2 pkg create --build-type ament_cmake --license Apache-2.0 $pkg
done
ros2 pkg create --build-type ament_cmake --license Apache-2.0 rc_msgs
ros2 pkg create --build-type ament_cmake --license Apache-2.0 rc_description
```

### 步骤 4：构建并配置环境
```bash
cd ~/ROS2/27RC
# 初始化 rosdep（首次）
sudo rosdep init 2>/dev/null; rosdep update
rosdep install --from-paths src -y --ignore-src

# 编译
colcon build --symlink-install

# 加入环境（建议写入 ~/.bashrc）
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
echo "source ~/ROS2/27RC/install/setup.bash" >> ~/.bashrc
source ~/.bashrc
```

### 步骤 5：先做仿真，再上真机（强烈建议）
```bash
# 在 rc_sim 中搭建 1:1 场地 Gazebo 模型（按 README 尺寸）
# 先在仿真里验证：导航、爬楼、堆叠、行为树，再迁移到实体
sudo apt install -y ros-humble-gazebo-ros-pkgs
```

### 步骤 6：硬件落地顺序
1. 用现成的差速/全向底盘 + 手柄，先把 **TR 手动**跑起来（`rc_teleop`）；
2. BR 底盘先做"能爬斜坡"这一件事，验证通过再加机构；
3. 感知、堆叠、决策逐模块在仿真验证后上真机联调。
